# SP-8.2 — Rate-limit conformance coverage (`ref:conformance.saturate_op`)

**Date:** 2026-04-25
**Status:** Approved — ready for implementation plan
**Parent:** Closes the SP-operability-v1 §5.5 (Q5b=i) deferral.
**Anchor:** SP-8 spec §4.5 / §7.2 (gated-tool family pattern); SP-operability-v1 §5 (rate-limit semantics).

## 1. Context

SP-operability-v1 shipped `max_concurrent` enforcement with the new
`ERR_RATE_LIMITED = 1002` wire code, but its design Q5b=(i) deferred
the cross-impl conformance fixture: no built-in tool naturally
saturates, so the conformance suite couldn't validate 1002 the way
SP-8.1 validates 1001 via `ref:conformance.denied_op`.

This SP closes the gap with a sibling tool — `ref:conformance.saturate_op` —
gated behind the same `--enable-conformance-tool` flag, registered with
`max_concurrent: 1`, and permanently saturated by leaking its sole
permit at server startup. A single-shot conformance fixture then
triggers 1002 deterministically.

## 2. Decisions locked in during brainstorming

| # | Question | Answer |
|---|---|---|
| Q1 | How to permanently saturate the semaphore? | A — Box::leak the permit at server startup. ~64 byte leak, only with the flag, idiomatic Rust. |
| Q2 | Tool id + cap config? | `ref:conformance.saturate_op`; `required_capabilities: []` (clean separation from 1001 path); `max_concurrent: 1`; `tier: Some(Hot)`; trust L0Unverified; publisher "atd-ref-server". |
| Q3 | Wiring shape (builtin.rs returning the semaphore)? | (α) — keep `builtin_registry()` signature unchanged; main.rs uses existing `registry.get(...)` to fetch the saturate_op semaphore for leaking. |

## 4. `ConformanceSaturatedTool` implementation

`crates/atd-ref-server-bin/src/conformance.rs` (appended after `ConformanceDeniedTool`):

```rust
/// A trivial tool whose semaphore is permanently saturated by the
/// startup-time `Box::leak` in `main.rs`. Every call returns
/// `ERR_RATE_LIMITED` (code 1002) at the dispatch layer's
/// `try_acquire_owned` check, before `call` ever runs.
///
/// If `call` *does* run, that's a bug in the rate-limit gate or in the
/// startup leak — the `InternalError` sentinel makes the violation
/// loud rather than silently succeeding.
pub struct ConformanceSaturatedTool {
    def: ToolDefinition,
}

impl ConformanceSaturatedTool {
    pub fn new() -> Self {
        Self {
            def: ToolDefinition {
                id: "ref:conformance.saturate_op".into(),
                name: "conformance saturate op".into(),
                description:
                    "Test tool: registered with max_concurrent=1, then has \
                     its sole permit leaked at server startup so the \
                     semaphore is permanently empty. Exists only to let \
                     atd-conformance validate the ERR_RATE_LIMITED \
                     (code 1002) wire path. Enabled via \
                     --enable-conformance-tool."
                    .into(),
                version: "0.0.0".into(),
                capability: ToolCapability {
                    domain: "conformance".into(),
                    actions: vec!["saturate_op".into()],
                    tags: vec!["test".into()],
                    intent_examples: vec![],
                },
                input_schema: serde_json::json!({ "type": "object" }),
                output_schema: serde_json::json!({ "type": "object" }),
                bindings: vec![ToolBinding {
                    protocol: BindingProtocol::Cli,
                    config: serde_json::json!({}),
                }],
                safety: ToolSafety {
                    level: SafetyLevel::Read,
                    dry_run: false,
                    side_effects: vec![],
                    data_sensitivity: None,
                },
                resources: ToolResources {
                    timeout_ms: 1000,
                    max_concurrent: 1,
                    rate_limit_per_min: None,
                    estimated_tokens: None,
                },
                trust: ToolTrust {
                    publisher: "atd-ref-server".into(),
                    trust_level: TrustLevel::L0Unverified,
                    signature: None,
                },
                visibility: ToolVisibility::Read,
                required_capabilities: vec![],
                tier: Some(ToolTier::Hot),
            },
        }
    }
}

impl Default for ConformanceSaturatedTool {
    fn default() -> Self { Self::new() }
}

impl Tool for ConformanceSaturatedTool {
    fn definition(&self) -> &ToolDefinition { &self.def }

    fn call<'a>(&'a self, _args: serde_json::Value, _ctx: &'a CallContext) -> CallFuture<'a> {
        Box::pin(async {
            Err(ToolCallError::InternalError(
                "ref:conformance.saturate_op was reached by dispatch — \
                 startup permit leak should keep the semaphore empty so \
                 try_acquire_owned() always fails with code 1002"
                    .into(),
            ))
        })
    }
}
```

Unit test (mirrors SP-8.1 `definition_declares_conformance_denied_cap`):

```rust
#[test]
fn saturated_tool_definition_declares_max_concurrent_one() {
    let t = ConformanceSaturatedTool::new();
    let d = t.definition();
    assert_eq!(d.id, "ref:conformance.saturate_op");
    assert_eq!(d.resources.max_concurrent, 1);
    assert!(d.required_capabilities.is_empty());
    assert_eq!(d.trust.publisher, "atd-ref-server");
    assert_eq!(d.trust.trust_level, TrustLevel::L0Unverified);
    assert_eq!(d.tier, Some(ToolTier::Hot));
}
```

## 6. `main.rs` startup-time leak

After `let registry = builtin_registry(args.enable_conformance_tool);` and
before `Server::new(...)`:

```rust
    // SP-8.2: when the conformance tool family is enabled, permanently
    // saturate ref:conformance.saturate_op so the conformance suite's
    // rate-limited fixture sees a 1002 on every single-shot call. The
    // leaked permit lives for the entire process lifetime —
    // intentional, documented, ~64 bytes.
    if args.enable_conformance_tool {
        let entry = registry
            .get("ref:conformance.saturate_op")
            .expect("ref:conformance.saturate_op registered when --enable-conformance-tool is set");
        let permit = entry
            .semaphore
            .clone()
            .try_acquire_owned()
            .expect("saturate_op semaphore should have its single permit available at startup");
        Box::leak(Box::new(permit));
    }
```

The leak only fires when the flag is set. Production deployments
(no flag) pay zero overhead — neither tool is registered, no permit
is acquired, no leak.

## 7. Conformance fixture

`crates/atd-conformance/fixtures/behavior/rate_limited_returns_code_1002.json`:

```json
{
  "category": "behavior",
  "name": "rate_limited_returns_code_1002",
  "description": "Calling a tool whose max_concurrent permits are exhausted returns Response::Error { code: 1002, retryable: true }. Requires the target server to expose a permanently-saturated tool — the atd-mvp reference server does this via `ref:conformance.saturate_op` (registered with max_concurrent=1 when `--enable-conformance-tool` is passed; its sole permit is leaked at server startup so any client call finds the semaphore empty). Third-party servers that want to validate this case must expose a tool with id `ref:conformance.saturate_op` declaring max_concurrent=1, and arrange for that permit to be permanently held (e.g., on startup) so single-shot client calls always hit the rate-limit path.",
  "setup": null,
  "send": {
    "type": "run_tool",
    "tool_id": "ref:conformance.saturate_op",
    "args": {},
    "dry_run": false
  },
  "expect_response_matches": {
    "type": "error",
    "code": 1002,
    "retryable": true
  }
}
```

`setup: null` because saturate_op declares `required_capabilities: []`
— no Hello handshake needed. The deep-subset matcher allows the server
to include extra fields (`details.tool_id`, `details.limit`,
`message`) without the fixture asserting on them.

## 9. Non-goals

| Not doing | Why | When it opens |
|---|---|---|
| Multi-concurrent request fixture testing real saturation race | Single-shot deterministic 1002 is the wire-contract goal; concurrent races are dispatch-internal | Token-bucket SP needs concurrency anyway |
| Asserting `retry_after_ms` field non-null | Always `None` in v1 (no token bucket); fixture's deep-subset matcher allows the field to be absent | Token-bucket SP populates it |
| Exposing `ConformanceSaturatedTool` as a public lib API | YAGNI — only ref-server-bin's own main.rs uses it | Never (test-only tool by design) |
| Adding rate-limited cases under the `wire` category | This is a behavior-level case (server-side semantic, not byte-level) | — |
| Modifying self-conformance test spawn or assertions | Already covers `--enable-conformance-tool`; case count window allows growth | — |
| `docs/architecture.md` §10 row flip | Rate-limit row already flipped to ✅ in SP-operability-v1 C3 | — |
| Per-impl variation test (e.g., the saturate_op tool's exact `max_concurrent` value) | Spec text in fixture description says "must declare max_concurrent=1"; that's the contract | — |

## 10. Success criteria

1. **4-gate green** on the single commit (fmt + clippy + test + release build).
2. **Default behavior** (no flag) unchanged: 10 tools registered (9 on non-unix).
3. **With `--enable-conformance-tool`**: 12 tools registered (10 + denied_op + saturate_op); saturate_op semaphore at 0 permits after startup.
4. **CLI smoke**: `atd call ref:conformance.saturate_op` against a flag-enabled server returns `Response::Error { code: 1002, retryable: true }` immediately (no blocking, no timeout).
5. **Self-conformance test passes**: `report.total == 33`, `report.failed == 0`.
6. **Workspace test count**: 333 → 334 (+1 from the new `saturated_tool_definition_declares_max_concurrent_one` unit test; the rename of `..._adds_one` → `..._adds_two` is net 0).
7. **Zero changes** to `atd-protocol`, `atd-runtime`, `atd-sdk`, any `atd-tools-*`, or any other crate outside `atd-ref-server-bin` + `atd-conformance`.
8. **Zero CI YAML changes.**
9. SP tagged `sp-8.2-rate-limit-conformance` on completion.

## 11. Rollback

`git tag pre-sp-8.2-rate-limit-conformance` before the commit. The
single commit is independently revertable; `git revert <sha>` removes
the tool, the fixture, and the leak in one step.

## 12. Next steps unlocked

- **Token-bucket rate limit (SP-operability-v2 candidate)**: with both 1002 wire path and conformance coverage in place, the next iteration adds `rate_limit_per_min` enforcement using `governor` or a hand-rolled token bucket. The same `Outcome::RateLimited` audit variant gains a populated `retry_after_ms`.
- **Production rate-limit metrics**: an audit-log consumer can already count `outcome.kind == "rate_limited"` events. A future Prometheus / OTel exporter SP can expose these as gauges.
- **Cross-impl conformance for any future error code**: this SP establishes the "leak a setup primitive at startup" pattern. SP-8.3 (when needed) will use the same approach for whatever protocol path the spec next normalizes.
